## 確かめたこと

### 1. 内蔵の画面が e57549b の 4 ファイルと一致するか → 一致

- tar.gz を展開して md5 を取った。4 ファイルとも、知らせと同梱の MD5SUMS に一致した（合計 401,580 B）。
- `app/assets_gen.c` の 4 つの配列を取り出して gzip を解くと、md5 は次のとおり。

| ファイル | 元の大きさ | gzip 後 | md5 | 知らせと |
|---|---|---|---|---|
| index.html | 474 | 295 | e8028e8981def16e6970475e525bce0f | 一致 |
| assets/index-BtaxsJQv.js | 317,460 | 106,411 | e53182a7fb4e4a4a544d71bba7272a21 | 一致 |
| assets/index-ChhhKVz2.css | 72,972 | 13,703 | 9169cc2e0e015790501c4ca81dd34f19 | 一致 |
| assets/miseru-logo-BDPdv9c5.svg | 10,674 | 2,033 | e0c577bd55ab3a3f5bde68a495fa987c | 一致 |

- さらに、展開したフォルダから `tools/mkassets.py` で `assets_gen.c` を作り直した。置いてある `app/assets_gen.c` と **1 バイトも違わなかった**（gzip 後の合計 122,442 B）。
- 試験版を Playwright の Chromium で開くと、左上に「rev 0.2.0-dev · build 564 / e57549b」と出た。WebSocket でロックが取れ、エラーは 0 件。`/api/settings` の version は "0.3.5"。

### 2. v0.3.4 から変わったのは画面と版の表記だけか → そのとおり

- v0.3.4 のソースは置いていないので、ビルドで確かめた。今のソースの `assets_gen.c` を v0.3.3 の内蔵の画面（9b04538）に戻し、`FW_VERSION_STR` を "0.3.4" に戻してビルドした。結果は `build/v0.3.4/ode_main.hex` と、ビルド時刻の 4 バイト（05:41:52 と 05:58:36 の違う桁）を除いて一致した（大きさ 194,480 B）。
- つまり、v0.3.4 → v0.3.5 で変わったのは `app/assets_gen.c` と `app/app.h` の版だけ。ほかのソース（box_core・http・minijson など、v0.3.4 で変わった所）は、v0.3.4 の hex を作ったものと同じ。
- app/・port/・tools/・Makefile で、v0.3.3（前にチェックした版）からほかに変わっているのは box_core.c/h・http.c・minijson.c/h。これは README の v0.3.4 の行（箱の名前を status と /api/dmx に足した）の分で、今回の範囲の外。

### 3. hex が今のソースから作ったものと合うか → 合う

- 今のソースをビルドし直すと、置いてある bin との違いはビルド時刻の 3 バイトだけだった（`__TIME__` の 8 文字のうち違う桁）。
- 置いてある hex を bin に直すと、置いてある bin と一致した。
- 置いてある elf から作った bin も、置いてある bin と一致した。map は、ビルドし直したものと差が無かった。前回の低 3（elf・map が古い版のまま）は解消している。
- 版の文字列は "0.3.5"（bin と elf の両方）。bin は 194,444 B で、セクタ 0〜5 に収まる。
