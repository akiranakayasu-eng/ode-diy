## 指摘

### 低

1. **初期化の押し方が足りない。** /setup の「SW2 を押したまま電源を入れると…初期値に戻ります」は、実際には電源を入れてから **1.5 秒押し続ける**必要がある（`port/stm32/main.c` の `boot_button_check`、50ms×30 回）。すぐ離すと何も起きない。合図の「LED 2 つが 5 回点滅」も、/setup には書かれていない（README の表には書いてある）。「押したまま電源を入れ、LED 2 つが 5 回点滅するまで（約 2 秒）押し続ける」とするとよい。
2. **「ファームを更新しても残る」には条件がある。** STM32CubeProgrammer で「Full chip erase」をすると、セクタ 11 の設定も消える。そのときは初期値（IP 192.168.1.223、PIN 1234）で起動する。README の書き込み手順は「Full chip erase はしない」と書いているが、/setup の説明は無条件に「残ります」になっている。「（書き込みで全消去をしなければ）」を足すか、「消えても初期値 1234 で起動する」と書くとよい。

## 結論（追加分）

**高 0・中 0・低 2（新しいもの）。** `pin_default` から PIN の値は漏れない。上の低 2 件（1.5 秒押し続ける、Full chip erase）は、追加分でも文が変わっておらず残っている。v0.3.2 全体では **高 0・中 0・低 4**。

## 確かめたこと

- **hex がこのソースから作られているか:** ビルドし直すと、置いてある bin との違いはビルド時刻の 3 バイトだけだった。hex を bin に直すと一致した。
- **`pin_default` から PIN が漏れないか:**
  - `pin_default` は `strcmp(g_settings.pin, "1234") == 0` の結果を `true`／`false` の 2 つの文字だけで返す（http.c 314 行）。PIN の文字列を JSON に書く所は無い（`GET /api/settings` の書式は PIN を含まない）。
  - 試験版で、PIN を 5555 に変えると `pin_default:false` になり、応答に `5555` は含まれなかった。1234 に戻すと `true` に戻った。
  - 分かるのは「いまの PIN が初期値の 1234 かどうか」だけ。1234 のときは誰でも試せば分かる値（README と /setup に書いてある）で、それ以外のときは何も分からない。
- **画面:**
  - スクリプトは `node --check` で文法エラーなし。
  - 色は、注意（RESET ではない方、10 秒で LAN と DMX が止まる）が赤（`#b00020`）、秒数と 1234 が茶色（`#8a4b00`）。PIN の状態の帯は、初期値のままなら薄橙の地に茶色の文字、変更済みなら薄緑の地に緑の文字。値は `textContent` で入れている。
