## PIN を外した API が窓で守られているか

| API | 要るもの | 試験版で窓が閉じているとき | 窓が開いているとき |
|---|---|---|---|
| `POST /api/pin`（新しい PIN だけ） | 窓だけ（いまの PIN は要らない） | 403 `{"ok":false,"error":"button"}`（`pin=1234` を付けても同じ） | 200 `{"ok":true}` |
| `POST /api/ui`（差し替え） | 窓だけ | 403 button | — （前回までに確認済み、コードは変わっていない） |
| `POST /api/ui/reset` | 窓だけ | 403 button | 同上 |
| `POST /api/dfu` | 無い | 405 | 405 |
| `POST /api/settings` | PIN（窓は要らない） | — | — |

- `/api/pin` は最初の行（http.c:495）で窓を調べ、閉じていれば本文を読む前に断る。
- 窓を開けるのは SW2 の 3 秒長押しだけで、HTTP や WebSocket から開ける道は無い（前回までと同じ）。
- `/api/pin` の値のチェック（窓を開いて試した）:

| 送ったもの | 返事 |
|---|---|
| 空 | 400 value |
| 16 文字 | 400 value |
| 15 文字 | 200 |
| `newpin` が無い | 400 value |

- PIN を変えたあと（再起動なし）:
  - `/api/settings` は古い PIN だと 403 pin、新しい PIN だと通る。
  - WebSocket の `pin` は新しい PIN で ok、古い PIN で ng。
  - フラッシュへの保存も呼ばれている（試験版のログ）。

## 指摘

### 低

1. **README 11 行がまだ古い。** 「画面の差し替え・内蔵の画面に戻す・**ファーム更新モード**は、SW2 を 3 秒押し続けてから 10 分の間だけ受ける」のまま。v0.3.1 ではファーム更新モードは 10 秒の押し続けで入り、窓の間に受けるのは「差し替え・戻す・**PIN の変更**」になった。表（33〜35 行）と 56 行は直っている。
2. **「一瞬光って」は見えないかもしれない。** `plat_enter_dfu` の待ちは `for` 200,000 回（`port/stm32/board.c:126`）で、168MHz では数 ms〜十数 ms ほど。LED が光ったと分からないくらい短いかもしれない。分かりやすい合図は「D6 STAT の点滅が止まって、2 つとも消える」の方。実機で見え方を確かめるとよい（作者が実機で試すとのことなので、そのときに）。
3. **窓の間は、LAN の誰でも PIN を書き換えられる。** その PIN で、窓が閉じたあとも `POST /api/settings`（IP・許可リストなど。窓は要らない）を使える。さらに、窓の間に 作者のブラウザが開いたほかのサイトのページから、`/api/pin` に POST されることもありうる。いずれも本体のボタンを押せる人が窓を開けている 10 分の間だけで、決定（PIN は Admin 用だけ）どおりなので低。前々回からの「PIN で画面に出ない設定も変えられる」と同じ根っこ。
4. **PIN を変えても、すでに Admin に入っている接続はそのまま。** WebSocket で古い PIN を通した接続は、PIN を変えたあとも Admin のままでいられる（`box_core` は通ったことを覚えていて、変えたときに取り消さない）。v0.3.0 で再起動なしにしたときからある。PIN を忘れて入れ直す使い方なら困らない。
