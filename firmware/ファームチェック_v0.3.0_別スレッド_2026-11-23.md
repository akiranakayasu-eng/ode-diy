## 確かめたこと

### フラッシュのセクタ番地（出典との照合）

| セクタ | 先頭番地 | 大きさ | v0.3.0 での使い道 |
|---|---|---|---|
| 0〜3 | 0x08000000 / 4000 / 8000 / C000 | 16KB×4 | ファーム |
| 4 | 0x08010000 | 64KB | ファーム |
| 5〜7 | 0x08020000 / 40000 / 60000 | 128KB×3 | ファーム（ここまで 512KB） |
| 8〜10 | 0x08080000 / 0x080A0000 / 0x080C0000 | 128KB×3 | 画面の差し替え（384KB） |
| 11 | 0x080E0000 | 128KB | 設定 |

- 出典: ST の STM32CubeF4 の例 `Projects/STM32F4-Discovery/Examples/FLASH/FLASH_EraseProgram/Inc/main.h` の `ADDR_FLASH_SECTOR_0〜11`（GitHub STMicroelectronics/STM32CubeF4）。FLASH_CR の SNB は bit 3〜6、PSIZE は bit 8〜9（同梱の `vendor/cmsis_f4/stm32f407xx.h`）。
- **RM0090 の表 5 は画像で見られていない。** この環境では st.com が 403（curl）で、WebFetch では目次しか読めなかった。上の番地は ST の公式サンプルとの照合。PDF を作業フォルダに置いてもらえれば、表を画像で見て照合し直す。
- `F4_SECTOR_ADDR(n)` は上の表と一致（n=8 → 0x08080000、10 → 0x080C0000、11 → 0x080E0000）。`_Static_assert` 2 本も正しい。
- リンカ: FLASH の長さ 512K = セクタ 0〜7 の合計（16×4+64+128×3 = 512KB）と一致。実際の像は 0x08000000〜0x0801E770（約 122KB）で、画面の区画と重ならない。
- `UI_MAX` = 384KB − 16 = 393,200。アップロードの上限判定と `plat_ui_write` の範囲判定は合っている。
- 消去: 先頭のセクタだけ消してから、書き込みが次のセクタに入るときにそのセクタを消す（`ui_erased_end`）。アップロードのたびに 8 から消し直すので、前の大きい画面の残りが邪魔をすることはない。見出し（先頭 16 バイト）は最後に書くので、途中で切れれば内蔵の画面に戻る。

### ビルドと試験版

- ARM 版を gcc-arm-none-eabi 13.2 でビルドし直し、置いてある `build/ode_main.bin` と比べた。違いは 4 バイトだけ（`__TIME__` の 02:48:30）で、大きさも同じ 124,784 バイト。置いてある hex はこのソースから作られている。
- 試験版（TAP）で確かめた結果:

| 試したこと | 結果 |
|---|---|

## 指摘

### 中

**中 1. 長押しで窓を開くと、必ず先に「ロック解除と全消灯」が起きる。** `port/stm32/main.c:109` は押した瞬間に `app_button()`（ロック解除と全消灯、公演モード中も）を呼び、3 秒たったら窓も開く。長押しは「短押しの動作＋窓」になっていて、短押しと区別されていない。公演中や誰かが操作している最中に画面を差し替えようとすると照明が消える。/setup の文（`app/setup_page.h:28`「短く押すと今までどおりロック解除と全消灯です」）は、長押しなら消えないように読める。試験版の `l` も `app_button()` を先に呼ぶ（`port/host/main.c:92`）ので同じ。
出典: 11/20 依頼 3「短く押すと今は『ロック解除と全消灯』になるので、差し替えの許可は長押し（例: 3 秒）にするなど、今の動作と区別する案を出してほしい」。
案: ロック解除を「離したときに 3 秒未満なら」に移す（短押しの反応が少し遅れる）。今の形のままにするなら、/setup と README に「長押しでも全消灯する」と書く。どちらにするかは 作者が決めること。

### 低

1. **値は API で今も全部変えられる。** `POST /api/settings` は PIN があれば IP・許可リスト・名前なども変えられる（`app/http.c:364-431`）。11/20 依頼 1 は「画面から外す」なので違反ではない。ただし依頼 2 の「PIN は Admin に入るためだけ」とは少しずれるので、残すなら miseru 側 への知らせ（仕様の版）に書いておくとよい。
2. **README のケースを開けずに書き込む手順に長押しが無い。** `README.md:55` は「/setup で PIN を入れ、『ファーム更新モードにする』」のまま。v0.3.0 では先に本体ボタン 3 秒が要る（無いと `button` で断られる）。
3. **リンカスクリプトの注釈の番地が違う。** `port/stm32/stm32f407vg.ld:2`「セクタ 8〜10（0x080A0000、384KB）」。正しくは 0x08080000（0x080A0000 はセクタ 9）。動きには関係ないが、注釈を写すと同じ取り違えが起きる。
4. **窓は使ったあとも開いたまま。** 差し替え・戻す・DFU のあとも 10 分が終わるまで、LAN の誰でも PIN なしで差し替えと「内蔵の画面に戻す」ができる。成功したら窓を閉じる案がある（11/20 依頼は 10 分と指定しているので、閉じるかは 作者が決めること）。
5. **/setup の「もう一度押してください」があいまい。** `app/setup_page.h:24` の文「10 分以内にもう一度押してください」は、本体のボタンをもう一度押す（＝全消灯）とも読める。「この画面のボタンをもう一度押してください」にするとよい。
6. **画面を配っている最中に差し替え・戻すをすると、配っている途中の画面が壊れる。** `pump_file` はフラッシュの中身をコピーせずに lwIP に渡す（`app/http.c:79`）。送り終わる前や再送の前に `ui_upload_begin`／`ui_reset` がセクタ 8 を消すと、0xFF や新しい中身が送られる。v0.2.0 からある（v0.3.0 で起きたものではない）。v0.3.0 では PIN なしで消せるようになったので触れておく。ブラウザで開き直せば直る。
7. **長押しの点滅の 0.6 秒は LAN を読まない。** `main.c` の点滅は `board_delay_ms` で 600ms 止まるので、その間 Art-Net・sACN・WebSocket を読まない（番犬は蹴っている）。直前に全消灯しているので、出力への影響は無い。また、画面の消去が最大 3 回になり、そのたびに割り込みが 1〜2 秒止まって `g_ms` が遅れる（窓とロックの時間切れが少し延びる）。
8. **試験版で再起動の表示が止まらない。** 試験版の `plat_reboot` は何もしないので、`pending_reboot` が残り、`[reboot]` を出し続ける（`app/http.c:696`、`port/host/main.c:33`）。試験版だけで、実機には関係ない。v0.2.x からある。
