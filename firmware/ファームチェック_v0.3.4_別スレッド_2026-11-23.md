2. 試験版（TAP、192.168.1.223）を動かし、Chromium（Playwright）から `ws://192.168.1.223/ws` に hello を送って status を受け、`JSON.parse` した。`GET /api/dmx` と `GET /api/settings` も読んだ。
   - 名前 `ODE-DIY`: status・/api/dmx・/api/settings に `"name":"ODE-DIY"`。JSON として読める。
   - 名前 `a"b\c` + 0x01 + `d`（`POST /api/settings` で設定）: `"a\"b\\c\u0001d"` と逃がされ、3 か所とも JSON として読めた。
   - 名前 `照明箱テスト`（UTF-8 で 18 バイト）: 下の中 1。
3. `mj_escape` を単体で gcc に通した。17 バイト全部が制御文字のときの長さは 102 で、呼び出し側の `nm[112]` に収まる。出力先が足りないときは逃がし文字の途中で切らずに止まる。

## 中

### 中 1: 名前が 17 バイトで途中で切れると UTF-8 として壊れ、ブラウザが WebSocket を切る

- 場所: `app/http.c:388`（`strncpy(s.name, v, sizeof(s.name) - 1)`、17 バイトで切る）、`app/minijson.c:60-76`（`mj_escape` は 0x80 以上のバイトをそのまま通す）、`app/http.c:128-135`（status に入れる）
- 起きたこと（試験版で再現）: `POST /api/settings` で `name=照明箱テスト`（18 バイト）を入れると、名前は 17 バイト目で切れて最後の文字が壊れたバイト列になる。この名前を入れた status は UTF-8 として正しくないので、**Chromium は WebSocket をすぐ切る（error → close 1006）**。status は接続直後に必ず送るので、何度つなぎ直しても同じで、miseru の画面からは箱が使えない。`GET /api/dmx` は `fetch().json()` が置き換え文字（�）にして読めるので、壊れるのは WebSocket だけ。
- 名前は設定としてフラッシュに残り、ボタンの初期化（IP と PIN だけ戻す）でも戻らない。直すには `POST /api/settings` で名前を入れ直すしかない。
- 名前を変える欄は /setup に無く（v0.3.0 で外した）、`POST /api/settings` を直接たたいたときだけ起きるので「中」とした。17 バイトに収まる日本語（例: 5 文字の 15 バイト）なら壊れない。`%FF` のような UTF-8 でないバイトを直接入れても同じことが起きる。
- 直し方の案: 名前を保存するとき、17 バイトに切る位置を UTF-8 の文字の切れ目まで戻す（続きのバイト 0x80〜0xBF の前で切らない）。あわせて、UTF-8 として正しくない名前や 17 バイトを超える名前は `400 {"ok":false,"error":"value"}` で断る方が分かりやすい。ArtPollReply の短い名前（Art-Net では ASCII）にも同じ名前が入るので、名前を ASCII に限るのも一案。
- ついでに: `form_get` の `v[40]` で 39 バイトを超える名前も黙って切られ、返事は `ok:true`（v0.3.4 より前からの動き）。

## 低

### 低 1: 仕様 v1.1 の「/setup の名前」と今のファームが合わない

- 仕様 v1.1 は `name` を「/setup の『名前』」と書いているが、v0.3.0 から /setup に名前の欄は無く、変えられるのは `POST /api/settings`（PIN が要る）だけ。README の v0.3.4 の行には書いてあるが、仕様の側は古いまま。miseru 側 に「名前は POST /api/settings の name で変える」と伝えると食い違いが消える。

### 低 2: ソースの冒頭の仕様の版が v1 のまま

- `app/http.c:2` と `app/box_core.h:2` が「自作ODEのWebSocket仕様v0.md（v1）」。`name` は v1.1 で足したものなので（`box_core.h:59` の注釈は v1.1 と書いている）、冒頭も v1.1 にそろえると迷わない。

### 低 3: 注釈の「最大 17 文字」は 17 バイト

- `app/http.c:127` の「名前は最大 17 文字」は、実際には 17 バイト（日本語なら 5 文字）。中 1 とかかわるので、バイトと書いた方がよい。

### 低 4: box:check 14 件と実機は、このチェックでは確かめていない

- README の「試験版で box:check 14 件すべて通過」は、miseru がこのスレッドから読めないので、こちらでは流していない。名前の項目は、上の 2 の確かめ方（status と /api/dmx に name があり JSON として読める）で代わりに見た。実機は未確認（README のとおり）。

## 仕様と合っている所

- `status` に `"name"` がある（`box_core.c:175`）。接続直後（`http.c:465`）、変化したとき・1 秒ごと（`ws_broadcast_status`）のどれも同じ関数を通るので、全部に入る。
- `GET /api/dmx` の先頭に `"name"` がある（`http.c:284`）。並び順は仕様の例と同じ。
- `GET /api/settings` の `name` も同じ逃がし方になった（`http.c:304`、v0.3.3 までは逃がしていなかった）。
- 名前の初期値 `ODE-DIY` は ArtPollReply の短い名前と同じ設定から出ている（`settings.c:23`、`artnet.c:34`）。
- 空の名前は `POST /api/settings` が受けない（`v[0]` の確認）ので、`"name":""` にはならない。
- 0x7F（DEL）は逃がしていないが、JSON ではそのままで正しい。
