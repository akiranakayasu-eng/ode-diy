# ode_main rev B 回路図 1 版のチェック（2026-11-19、別スレッド）

## 結論

**修正要（高 0・中 4・低 9）。** 止まって動かなくなる誤りは見つからなかった。ESP32-S3 モジュールと W5500 のピン番号は全ピンでデータシートと一致した。中の 4 件は、W5500 のデータシートや参考回路と違う所と、部品とフットプリントの食い違い。どれも直すのは小さい。

照合のしかた: netlist.net を読み、部品ごとに全ピンの接続先を書き出して出典と並べた。参考回路（WIZnet）とモジュールの図 7（Espressif）は画像にして見た。電源・DMX まわりは、rev A のネットリストと同じ部品の同じピンどうしの接続を機械的に比べた。

## 指摘

### 高

なし。

### 中

**中 1. W5500 の 23 番ピン（RSVD）が未接続。GND につなぐ。**
- [W] 表 2: 「23 RSVD Pull-down I — It must be tied to GND.」改版履歴でも 38〜42 番は「GND に接続」から「NC」に変わったが、23 番は「GND に接続」のまま。
- 回路図: U3.23 は未接続のマーク（unconnected-(U3-RSVD-Pad23)）。
- 補足: 参考回路 [R] でも 23 番は × 印（未接続）になっていて、データシートと食い違う。内部にプルダウン（48〜174kΩ、[W] 5.3）があるので未接続でも動く見込みは高いが、データシートの「must」に合わせて GND に落とすほうが安全。損はない。

**中 2. 受信側の 49.9Ω × 2 の位置が参考回路と違う（コンデンサの W5500 側ではなくトランス側にある）。**
- [R]（画像で確認）: RXP・RXN は 0Ω（R23・R24）を通ったあと、**コンデンサ C9・C10（6.8nF）より W5500 側の点**から R6・R7（49.9Ω 1%）を出し、その中点を RCT（P1 の 5 番）と C15（10nF → GND）につないでいる。6.8nF の先がトランスの RD+・RD−。
- 回路図: R71 は ETH_RDP（J5.R3 = RD+、トランス側）と ETH_RCT の間、R72 は ETH_RDN（J5.R6 = RD−）と ETH_RCT の間。W5500 の RXP・RXN（U3.6・U3.5）には C63・C64 しかつながっていない。つまり終端がトランス側にあり、W5500 のピンは直流的にどこにもつながらない。
- 影響: 交流では 100Ω の終端としてほぼ同じに働く見込みだが、W5500 の受信ピンの直流の動作点が参考回路と違う。実績のある形からわざわざ外れる理由がないので、[R] のとおり R71・R72 の片側を U3 側（ETH_RXP・ETH_RXN）へ移すのを勧める。

**中 3. F1（PTC 1.1A）のフットプリントが rev A の 1206 から 0805 に変わっている。**
- rev A: F1「PTC 1.1A/6V」Fuse_1206_3216Metric、部品リスト_revA.md は 0ZCJ0110FF2E（1206）。
- rev B: F1「PTC 1.1A」Fuse_0805_2012Metric。型番の指定なし。
- 「電源は rev A と同じ回路」の前提だと、rev A の部品は載らない。0805 のまま行くなら、0805 で保持 1.1A・6V 以上の型番を決めて部品表に書く（その型番の定格は未確認）。1206 に戻すほうが簡単。

**中 4. EN（リセット）を JST ケーブルで天板へ出している。**
- [H] CHIP_PU: 「To avoid reboots caused by external interferences, make the CHIP_PU trace as short as possible.」
- 回路図: /EN は U1.3・R31（10k）・C33（1µF）・SW1 のほかに J6.3（天板 JST PH 8P）へ出ている。ケーブルの長さだけ EN が長くなり、静電気やノイズで再起動しやすくなる。
- 案: 天板のリセットは GPIO に入れてソフトで再起動する（EN は基板の中だけにする）か、EN と J6.3 の間に直列抵抗（例 1kΩ 程度）を入れて天板側の線を EN から切り離す。どちらにするかは運用（固まったときに天板から戻したいか）で決める。

### 低

**低 1. DE（IO18）は電源投入時に High の時間がある。** [H] Power-Up Glitches: GPIO18 は「Low-level/High-level glitch」約 60µs。R74（10k プルダウン）は出力のグリッチを止められない。同時に IO17 も Low のグリッチ（60µs）があるので、電源投入時に DMX 線へ約 60µs の Low が出ることがある。DMX のブレーク（88µs 以上）より短く、受け手が 1 回フレームエラーを見るくらいの影響の見込み。気にするなら DE を表に載っていないピン（IO21、IO38〜42、IO47・48 など）へ移す。

**低 2. TX_M（IO17）はリセット中と起動直後に入力（プルなし）になり、U7（74AHCT1G125）の入力が浮く。** [H] IO Pin Default Configuration: GPIO17 は At Reset/After Reset とも IE のみ。DE は Low に保たれるので線には出ないが、CMOS 入力が浮く。TX_M に 10k のプルアップ（アイドル = マーク = High）を足すと落ち着く。rev A でも同じ考えだったかは未確認。

**低 3. USB D+／D− に直列抵抗の場所が無い。** [H] USB: 「It is recommended to reserve series resistors (initial value can be 22/33 Ω) and capacitors to ground on the traces (initially can be unpopulated)」。図 7 でも R4・R6（0Ω）と C5・C6（未実装）の場所がある。0Ω の場所だけでも取っておくと後で直せる。

**低 4. W5500 の SPI の SCLK に直列抵抗とコンデンサの場所が無い。** [H] SPI: 「add a series resistor (or ferrite bead) and a capacitor to ground on the SPI_CLK trace」。Wi-Fi と同じ基板なので、0Ω（または 22〜33Ω）の場所を取っておくのを勧める。SPI の速さは [W] 5.5.4 で「80MHz は理論値、保証は 33.3MHz」なのでファームでは 33MHz 以下から始めるのが無難。

**低 5. UART0 の TX（J4 へ）と UART1 の TX（DMX）に直列抵抗が無い。** [H] UART: U0TXD に 499Ω、ほかの UART の TX にも直列抵抗を勧めている。

**低 6. 水晶の XO 側に直列抵抗（0Ω）の場所が無い。** [W] 図 3 と [R] は XO と水晶の間に R17／R5（0Ω）を置いている（ドライブレベル調整用）。C51・C52 の 18pF、R60 の 1MΩ は図 3・[R] と一致。Y2 は型番が回路図に無いので、[W] 5.5.3 の「負荷容量 18pF、±30ppm、シャント容量 7pF 以下」に合う型番を部品表で決めること（rev A の FA-238 25.0000MB-K がこれに合うかは未確認）。

**低 7. RJ45 の 75Ω の共通点（J5.R8）を GND につないでいる。参考回路は CGND（筐体）。** [R]: P1 の 8 番 GHs_GND は CH_GND とともに CGND へ、CGND と GND は C16（1nF/2kV）で結ぶ。回路図: J5.R8 → GND、J5.SH → CHASSIS（R73 1M と C61 1n/2kV で GND へ）。KiCad のシンボルでは R8 の内側に 1000pF があるので直流的には問題ないが、[R] に合わせるなら R8 を CHASSIS へ。rev A と同じつなぎ方なので、変えるかは好みの範囲。

**低 8. USB-C は CC に 5.1kΩ だけで、ソースが何 A 出せるかを見ていない。** 3.3V 側だけでピーク約 0.5A（ESP32-S3 355mA [E] 表 12 ＋ W5500 132mA [W] 5.4 ＋ LED）、5V 側に ADM2587E（データシート未照合）が乗る。PC の USB（500mA）だと足りないことがある。運用で 1.5A 以上の充電器にする前提なら、CC1・CC2 の電圧を ESP32 の ADC で読めるようにしておくと、ファームで「電源が弱い」を知らせられる。

**低 9. 3.3V LDO（MCP1826、SOT-223）の発熱。** 損失 = (5.0−3.3)V × 電流。ピーク 0.5A で約 0.85W、平常（Wi-Fi 受信 ＋ W5500 リンク ＋ LED、約 0.25A）で約 0.43W。SOT-223 の熱抵抗は MCP1826 のデータシートが読めず未確認。N16R8 は周囲温度 65℃まで（[E] 表 10・型番表）なので、PCB で LDO を ESP32 モジュールから離し、銅箔を広く取ること。

## 問題なしと確かめた所

ESP32-S3-WROOM-1-N16R8（[E]）
- 41 ピンすべての番号と名前が表 3 と一致（1 GND、2 3V3、3 EN、4〜7 IO4〜7、8 IO15、9 IO16、10 IO17、11 IO18、12 IO8、13 IO19＝USB_D−、14 IO20＝USB_D+、15 IO3、16 IO46、17〜22 IO9〜14、23 IO21、24 IO47、25 IO48、26 IO45、27 IO0、28〜30 IO35〜37、31〜35 IO38〜42、36 RXD0、37 TXD0、38 IO2、39 IO1、40 GND、41 EPAD）。
- IO35〜37 は未接続（表 3 注 b: N16R8 は OSPI PSRAM が使う）。
- ストラップ: IO0 は R32（10k）で 3V3 へ＋SW3 で GND（表 6: IO0=0・IO46=0 で Download Boot）。IO46・IO45 は未接続で内部プルダウン（表 4）、IO45=0 で VDD_SPI 3.3V（表 7）。IO3 は未接続（表 8: eFuse が初期値なら無視される）。
- W5500 の SPI に使う IO10・11・12・13 は FSPICS0・FSPID・FSPICLK・FSPIQ（表 3）で、IO_MUX のピン。
- IO17 は U1TXD（表 3）。
- 電源: 3V3 に C31 22µF ＋ C32 100nF（図 7 の C1 22µF・C3 0.1µF と同じ）。外部電源 0.5A 以上（表 10）に対し MCP1826 は 1A 品。
- EN: R31 10kΩ ＋ C33 1µF（図 7 の下の注記の推奨値）、SW1 で GND。

W5500（[W]・[R]）
- 48 ピンの番号と名前が表 2・図 1 と一致。
- AVDD（4・8・11・15・17・21）は FB2（BLM21PG221SN1D）の先の +3V3A、100nF × 6（C55〜C60）＋ 10µF（C66）。[R] の C1〜C7 と同じ数と値。VDD（28）は +3V3 に C67 10µF ＋ C68 100nF（[R] の C11・C12 と同じ）。
- 1V2O に 10nF（C53）、TOCAP に 4.7µF（C54）、EXRES1 に 12.4kΩ 1%（R61）→ GND、VBG は未接続（「must be left floating」）、DNC・NC（7・12・13・46・47）は未接続、RSVD 38〜42 は未接続（「NC」）。
- PMODE0〜2 は未接続 → 内部プルアップで 111（全モード・オートネゴ）。
- 送信: TXP（2）→ J5.R1 TD+、TXN（1）→ J5.R2 TD−、それぞれ 49.9Ω 1%（R69・R70）で +3V3A へ。TCT（J5.R4）は R75 10Ω 1% で +3V3A から、C62 22nF で GND（[R] の R1・R2・R3・C8 と同じ）。
- 受信: RXP（6）→ C63 6.8nF → RD+（J5.R3）、RXN（5）→ C64 6.8nF → RD−（J5.R6）、RCT に C65 10nF（[R] の C9・C10・C15 と同じ。抵抗の位置だけ中 2）。
- 水晶: Y2 25MHz、C51・C52 18pF、R60 1MΩ を XI・XO 間（図 3・[R] と同じ。0Ω の場所だけ低 6）。
- LED: LINKLED（25）→ R67 330Ω → J5.L3、ACTLED（27）→ R68 330Ω → J5.L2、L1・L4 は +3V3（[R] の R8・R9 330Ω と同じ。出力は Low で点灯 [W] 表 2）。電流は (3.3 − Vf − 0.4)/330 で Vf 2V なら約 2.7mA、IOL 8.6mA 以上（[W] 5.3）の範囲。
- SCSn・INTn・RSTn に 10k プルアップ（R66・R65・R64）。RSTn は ESP32 の IO9 から 500µs 以上 Low にすればよい（[W] 5.5.1、ファームの仕事）。
- 入力の VIH は 2.0V（[W] 5.3）で、ESP32 の 3.3V 出力でよい。

RJ45（J5）
- KiCad 標準シンボルの図では L1→L2 が黄（Y）、L4→L3 が緑（G）で、L1・L4 がアノード。回路図の向き（L1・L4 を +3V3、L2・L3 を抵抗経由で W5500）と合う。rev A でも L1・L4 がアノード側だった。**ただし Amphenol の図面では確かめていない（読めなかった）。** トランスの巻数比とインダクタンスも未確認。

USB-C・電源・DMX
- J1: CC1・CC2 に 5.1kΩ（R1・R2）、D+ は A6・B6、D− は A7・B7、SBU は未接続、シールドは CHASSIS。
- 電源と DMX の部品（J1、F1、Q1、C1〜C6、U5、U6、U7、U9、U11、D11、J11、J12、FB101、FB102、C101〜C109、R101、D12、C61、C71、C73、R73、R74、D4、R29）は、rev A のネットリストと同じ部品の同じピンどうしの接続が完全に一致（機械的に比較）。XLR は 1 = GND_ISO、2 = Data−、3 = Data+。
- U7・U9（74AHCT1G125）は 1 番（OE）を GND で常に出力、VCC は +5V。
- ERC 0（erc.rpt）。未接続のマークの付いたピン以外に、つながる先が 1 つしかないネットは無い（ネットリストで確認）。
