# ode_main rev B ケース寸法モデル v4 の別スレッドチェック（2026-11-23）

## 結論

**高 0・中 1・低 2。**
- 前板の RJ45・XLR の穴は、PCB 4 版の部品の外形（F.Fab）の中心と合った。
- 原点の書き方も直った。
- アンテナの横と下の窓は、アンテナの根元の 1mm にかかっていない（中 1）。窓は奥行き方向に本体の後ろの辺 +1mm から始まるので、アンテナの根元（y 0〜1mm）の真横と真下には側板（4.5mm）と底板（6.6mm）が残る。
- 窓の縁も 15mm の内側に残る（低 1）。

成果物には手を入れていない。

対象: `case/case_model.py`・`dims.json`・`ode_revB_case.html`・`case_v4_確認図.png`（05:03 の版）、`ode_main_revB.kicad_pcb`（04:20 の版、PCB 4 版）。
- PCB の座標は kicad/kicad:10.0 の docker で pcbnew から読んだ。
- ケースの距離は case_model.py をそのまま読み込み、trimesh で板・側板・スペーサーの表面に点を 60 万個とってアンテナ部の箱までの距離を測った。
- 座標はケースの座標（前から見て左前の角・底板の上面が原点、x は右・y は奥・z は上、mm）。

出典: ESP32-S3-WROOM-1 データシート（7.2 推奨ランド図 Figure 10「Antenna Area 6」、18.0 × 25.5mm）、ESP32-S3 Hardware Design Guidelines 1.4.7（「Ensure that the PCB antenna on the base board also has a sufficiently large clearance area inside the housing. - 結果: **直った**。

## 中

### 中 1　窓がアンテナの根元の 1mm にかかっていない

- 窓は y = Y0 + 84 + 1（本体の後ろの辺から 1mm 後ろ）から始まる。アンテナ部は本体の後ろの辺（y 88.1）から始まるので、アンテナの根元の y 88.1〜89.1 の真横には右の側板（4.5mm）、真下には底板（6.6mm）が、窓の無いまま残る。最小の距離は v3 と同じで、窓を開けても横 4.5mm・下 6.6mm のまま。
- アンテナ部はモジュールの端の 6mm（DS 図 10）で、根元はモジュールの本体とつながる側。窓はその根元の 1mm を外している。
- コメントの「H3 のスペーサーの座を残す」は合わない。H3 はケースの x 10.1（左の側板の側）で、アンテナの近くにスペーサーは無い。いちばん近いのは H1 で 22.1mm。
- 案: 窓の前の端を、本体の後ろの辺より前へ出す。たとえば Y0 + 84 − 15 = 73.1 まで出すと、根元から前へも 15mm 開く。底板は本体の下なので、本体を支えるスペーサー（H1 の y 63.6）にもかからない。少なくとも Y0 + 84 より前にする。

## 低

### 低 1　窓の縁が 15mm の内側に残る

- 上の表のとおり、窓の縁（側板の下の帯 5.8mm、底板の右の帯 7.5mm・左 8.3mm、側板の後ろ 13.8mm）は 15mm の内側にある。ガイドの「全方向に 15mm」をそのまま満たすには、窓を次のように広げる必要がある。
  - 底板の窓の左を x 49.6 まで（√(13.5² + 6.6²) = 15）。
  - 側板の窓の下を z 0 まで（側板は窓の前後でつながるので形は保てる）。
  - 底板の右の帯は側板を受けるのに要るので残す。
- 縁は細い帯なので、面で覆うより影響は小さい。広げるか、ケースに入れて RSSI を比べて決めるとよい。どこまでやるかは 作者の判断。

### 低 2　HTML の XLR の穴の径がモデルと違う

- HTML は「XLR の前の板の穴（φ22 と取り付けねじ）」、モデルは hole_r = 11.5（φ23）。F.Fab の筒の幅は 22.1 なので、φ22 では入らない。どちらかにそろえ、Neutrik の図面で決める。

## 確かめていないこと

- NC3FAH のパネルの穴の寸法とねじの位置（Neutrik の図面を見ていない）。
- 窓をあけた側板（下の帯 3mm）と底板（右の帯 4.6mm）の強さ。
